# `/app` 实时解读页 UI 设计说明

日期：2026-05-10

## 目标

将 `/app` 实时解读页重构为“案牍工作台”式界面。页面的第一任务是让用户顺畅完成“输入具体问题 -> 起课 -> 阅读解读结果”，学习材料、反馈、测试状态、商业化兴趣和沙箱支付保留，但从首屏主流程降为辅助层级。

设计依据来自 `ui-ux-pro-max`：

- 产品类型：传统文化学习工具、实时解读应用、功能型工作台。
- 风格：Minimalism & Swiss Style，强调清晰网格、可读性、克制装饰。
- 色彩：深墨色 `#0F172A`、信任蓝 `#1E3A8A`、金色强调 `#CA8A04`、浅纸色背景 `#F8FAFC` 或偏暖纸色。
- 字体：中文内容优先使用宋/黑搭配，例如标题用 Noto Serif SC 或本地宋体，正文用 Noto Sans SC、Microsoft YaHei 或系统中文黑体。
- 避免：AI 紫粉渐变、过度玄学化装饰、低对比灰字、无标签表单、无加载/提交反馈。

## 设计方向

采用 A 方案：案牍工作台。

这个方向将页面分成三层：

1. 顶部状态层：品牌、主导航、MVP/安全边界提示。
2. 主工作区：左侧为提问与解读结果，右侧为课体摘要、学习材料、反馈与分享。
3. 次级实验区：Beta/Canary、商业化兴趣、沙箱支付等放到底部或折叠区。

不采用强聊天窗口方案，因为当前页面需要承载排盘、学习卡、出处、安全边界、反馈和实验功能。强聊天 UI 会让这些结构变得隐蔽，也会弱化“文化学习工具”的可信感。

## 信息架构

### 顶部

- 品牌：`澹语 · 大六壬`
- 导航：`起课`、`学习材料`、`反馈`、`沙箱`
- 状态提示：`文化学习体验 · 非现实建议`

顶部必须固定表达边界，不依赖用户滚动到法律或安全说明后才看到。

### 左侧主栏

第一块是“本次占问”：

- 多行问题输入框。
- 明确提示“输入一个具体事项”。
- 模式选择：白话、专业、故事、导师。
- 主按钮：开始起课。
- 连接、断开、打断等实时语音控制可以并入输入区旁的工具按钮或二级控制条，避免与主 CTA 同级竞争。

第二块是“解读结果”：

- 顶部显示安全状态或生成状态。
- 默认展示“结论”。
- 用分段标签组织：结论、依据、边界、原始数据。
- 长文本优先保证行高、段距和对比度。
- 出处卡、用神、天将等摘要以小卡形式跟在正文之后。

### 右侧辅助栏

右侧是用户阅读时需要顺手参考的信息：

- 课体摘要：模式、安全状态、学习卡数量、出处卡数量。
- 学习材料：天将角色卡、本次学习卡。
- 反馈与分享：反馈类型、备注、复制/生成分享报告入口。

右栏不放主要起课按钮，避免用户视线分散。

### 底部次级区

现有商业化、B2B、会员、沙箱支付、Canary 测试等模块保留，但默认进入底部或折叠面板。

- Beta/Canary：测试编号、邀请码、运维暂停提示。
- 商业化兴趣：会员、课程、B2B、IP 周边兴趣记录。
- 沙箱支付：订单创建、确认、失败、取消、退款。

这些模块不是主路径，视觉权重必须低于“提问”和“解读结果”。

## 视觉系统

### 色彩

- 页面背景：暖纸色或浅灰纸色，避免纯白大面积刺眼。
- 卡片背景：近白色。
- 主按钮：信任蓝。
- 重点状态和当前选中：金色。
- 风险/限制提示：低饱和红棕色。
- 正文：深墨色。
- 辅助文字：不低于 WCAG 4.5:1 对比要求。

### 字体

- 标题：宋体风格，表达传统文化感。
- 正文：清晰中文黑体，优先可读性。
- 不使用负字距，不使用随视口变化的字体大小。

### 组件

- 卡片圆角控制在 8px 左右。
- 按钮、模式切换、标签页都有稳定尺寸。
- 所有可点击元素必须有 `cursor: pointer`、悬停状态和键盘 focus 状态。
- 不使用 emoji 作为 UI 图标；需要图标时使用 SVG 或 Lucide 类图标。

## 交互与状态

### 起课流程

1. 用户输入具体问题。
2. 选择解读口吻。
3. 点击“开始起课”。
4. 页面显示加载状态，按钮进入处理中。
5. 解读结果区更新，默认展示结论。
6. 右侧同步更新课体摘要、学习材料和反馈入口。

### 失败与限制

- 不符合问题范围时，在输入区下方给出明确原因。
- 高风险问题只输出文化说明、安全提醒和求助建议。
- 运维暂停时，主 CTA 禁用并显示原因。
- 网络或 API 失败时，结果区显示可重试状态。

### 移动端

移动端按以下顺序纵向排列：

1. 顶部品牌和状态提示。
2. 本次占问。
3. 解读结果。
4. 课体摘要。
5. 学习材料。
6. 反馈与分享。
7. 次级实验区。

主 CTA 不能被折叠到屏幕过深位置。

## 需要改动的文件

预期主要改动：

- `static/realtime/index.html`
- `static/realtime/styles.css`
- 视实际 DOM 调整 `static/realtime/app.js`

`app.js` 的业务逻辑尽量不重写，只在必要时适配新的 DOM 结构和状态容器。

## 验收标准

- `/app` 首屏能明确看出“输入问题 -> 开始起课 -> 阅读结果”的主流程。
- 安全边界提示在首屏可见。
- 学习材料和反馈可见但不抢主流程。
- 商业化和沙箱支付不再占据首屏主要位置。
- 375px、768px、1024px、1440px 宽度下无文本重叠、按钮溢出或卡片错位。
- 表单有可访问标签，键盘 focus 状态可见。
- 加载、成功、失败、禁用状态都有明确反馈。

## 实施风险

- 当前 HTML 在终端读取时出现中文编码显示异常。实施前需要确认源文件真实编码，并用能保持 UTF-8 的方式编辑。
- 页面 DOM id 被 `app.js` 大量引用，重排 HTML 时必须保留或同步更新这些 id。
- 现有测试可能依赖具体文本或结构，实施后需要运行前端相关测试。
