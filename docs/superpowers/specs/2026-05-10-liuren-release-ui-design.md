# `release` 发布页 UI 设计说明

日期：2026-05-10

## 目标

将 `release` 发布页从“阶段状态列表”重构为“信任入口页”。页面第一任务是让首次访问者快速理解：

1. `澹语 · 大六壬` 是什么。
2. 当前 MVP 能体验什么。
3. 哪些现实建议和高风险问题明确不做。
4. 当前发布闸门和实验状态是否允许进入。
5. 如何进入 `/app` 实时解读页。

页面仍保留现有阶段状态和 JSON 链接，但它们不再占据首屏主叙事。

## 设计依据

使用 `ui-ux-pro-max` 生成的发布页设计系统，结合当前项目真实约束后采用以下取舍：

- 推荐模式：Scroll-Triggered Storytelling，但当前 MVP 更需要清晰入口，因此保留轻量叙事，不做复杂滚动动画。
- 推荐信任方向：Social Proof-Focused。项目不能虚构用户证言，所以信任证明改为真实可验证的范围、闸门、安全、隐私、版权和指标卡。
- 色彩：沿用 `/app` 的深墨色、信任蓝、金色强调和暖纸色背景，保持产品一致性。
- 字体：标题使用宋体风格，正文使用清晰中文黑体。
- 避免：复杂导航、隐藏联系方式或状态、虚构评价、过度玄学化装饰、AI 紫粉渐变、低对比文本。

## 方向

采用 A 方案：信任入口页。

首屏必须像真正的产品首页，而不是运维后台：

- 品牌 `澹语 · 大六壬` 是第一视觉。
- 一句话说明产品定位：传统文化学习与实时解读体验，不构成现实建议。
- 主 CTA：进入 Web App。
- 次 CTA：查看发布准入。
- 右侧展示产品预览卡，露出 `/app` 的起课和解读界面。
- 首屏下方展示三张信任卡：`MVP 范围`、`安全边界`、`当前状态`。

## 页面结构

### 顶部导航

导航应保持少而清楚：

- 品牌：`澹语 · 大六壬`
- 锚点：`范围`、`安全`、`状态`、`进入体验`
- 右侧小型 CTA：进入 Web App

导航不放过多阶段链接。阶段链接进入状态区后再展示。

### 首屏

首屏包含：

- Eyebrow：`受限发布准备版`
- H1：`澹语 · 大六壬`
- 副标题：`大六壬实时解读的文化学习入口`
- 说明文案：强调“学习、娱乐、可复盘”，同时明确“不构成医疗、法律、投资、人身安全或其他现实决策建议”。
- 主按钮：`进入 Web App`
- 次按钮：`查看发布准入`
- 产品预览卡：模拟 `/app` 中“本次占问 / 解读结果 / 安全边界优先”的工作台片段。

首屏底部展示三张信任卡：

1. `MVP 范围`：语音起课、文字起课、解释、学习卡、反馈。
2. `安全边界`：高风险问题降级，不承诺现实结果。
3. `当前状态`：从接口读取公开状态或运维状态。

### MVP 范围区

用两列或三列卡片说明：

- 已开放：语音起课、文字起课、专业/白话解释、故事/导师表达、出处卡、学习卡、本地分享报告、反馈记录。
- 关闭或限制：医疗、法律、投资、人身安全、隐私窥探、感情操控、应期承诺、未审校复杂断法。

这一区要比当前长段落更容易扫描。

### 发布状态区

保留现有状态读取能力，但组织为状态卡片：

- 运维状态
- Canary 准入
- 公开 MVP
- 产品化实验
- 商业化实验
- 支付准备

每张卡显示：

- 状态摘要。
- 一句解释。
- 相关 JSON 链接。

状态区服务于透明度，不抢首屏 CTA。

### 合规说明区

三张卡：

- 安全边界
- 隐私说明
- 版权说明

这些卡应靠近页面后半段，但仍在最终 CTA 前出现，让用户进入 `/app` 前有足够上下文。

### 最终 CTA

页面底部重复 CTA：

- 主按钮：`进入 Web App`
- 次按钮：`查看发布准入`

底部文案再次说明“文化学习体验，不构成现实建议”。

## 视觉系统

### 色彩

- 背景：暖纸色或浅米白。
- 主文字：深墨色。
- CTA：信任蓝。
- 强调：金色。
- 风险与限制：低饱和红棕色。
- 卡片背景：近白色。

不要把页面做成单一蓝色或单一米色。蓝色用于 CTA 和状态信任，金色用于当前选中和重点边界。

### 字体

- H1 和大标题：宋体风格，体现传统文化感。
- 正文和状态数据：中文黑体，优先可读性。
- 不使用负字距，不使用随视口宽度缩放的正文。

### 布局

- 首屏在桌面端使用左右分栏：左侧品牌与 CTA，右侧产品预览卡。
- 移动端顺序：品牌、定位说明、CTA、产品预览、三张信任卡。
- 页面宽度应比旧版更开阔，适合 1440px 桌面。
- 卡片圆角不超过 8px，避免过度圆润。
- 不使用嵌套卡片堆叠。产品预览卡可以是单独框，不再放入额外装饰容器。

### 动效

- 使用轻量 CSS hover 和过渡。
- 不做持续动画。
- 尊重 `prefers-reduced-motion`。

## 交互与状态

### 状态读取

保留当前页面的接口读取逻辑：

- `/api/ops/status`
- `/api/content/calendar`
- `/api/canary/metrics`
- `/api/public-release/gate`
- `/api/public/status`
- `/api/public/metrics`
- `/api/productization/gate`
- `/api/product/metrics`
- `/api/monetization/gate`
- `/api/monetization/metrics`
- `/api/payment/gate`
- `/api/payment/metrics`

现有脚本可以继续内联，或在实施计划中再决定是否拆到独立 JS 文件。当前设计不要求新增接口。

### 失败状态

接口失败时，状态卡显示“状态暂不可用”，并保留 JSON 链接。

### CTA 行为

- `进入 Web App` 链接到 `/app`。
- `查看发布准入` 链接到 `/api/release/readiness`。
- 状态卡的 JSON 链接保持现有目标。

## 需要改动的文件

预期主要改动：

- `static/release/index.html`
- `static/release/styles.css`
- 视测试需要调整 `tests/test_phase12_public_launch.py`、`tests/test_phase13_productization.py` 或已有 release 页面契约测试。

不需要改 `/app` 页面。

## 验收标准

- 首屏能明确看到 `澹语 · 大六壬`、产品定位、主 CTA 和安全边界。
- 首屏有产品预览，不只是文字说明。
- MVP 范围和限制范围可扫描，不是大段文本堆叠。
- 发布状态仍能读取并展示现有接口结果。
- 安全、隐私、版权说明可见，并位于最终 CTA 之前。
- 375px、768px、1024px、1440px 宽度下无文本重叠、按钮溢出或卡片错位。
- 链接和按钮有可见 hover 与 keyboard focus 状态。
- 无虚构用户证言、评分、客户 logo 或不可验证的社会证明。

## 实施风险

- 当前 release 页内联脚本较长，重排 DOM 时必须保留所有被 `getElementById` 使用的 id。
- 现有测试可能依赖旧文案，如 `壬语 MVP`、`MVP 范围` 或阶段标题，实施前需要先写新契约测试再调整页面。
- 发布页和 `/app` 已经共享相近视觉语言，但 CSS 文件分离，实施时需要复制设计 token 而不是引入跨目录依赖。
