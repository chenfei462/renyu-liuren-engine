# Question Auto Category Design

## Goal

为普通自然语言问句补上自动归类能力，让未显式传入 `category` 的低风险问题也能稳定命中对应的 `Q-*` 分类，从而带动 `category_symbols`、神将卡和学习资料随问题主题变化。

## Scope

- 修改后端问题归类逻辑。
- 保持现有 API 结构不变。
- 不修改前端渲染协议。
- 不放宽任何高风险拦截规则。
- 不调整现有神将映射表 `CATEGORY_CLASSIC_SYMBOLS`。

## Current Behavior

- `engine.py` 会调用 `normalize_category(category, question)` 决定最终分类。
- `safety.py` 当前只对高风险问题做关键词归类。
- 对大多数普通问句，如果调用方没有显式传 `category`，最终结果通常是 `None`。
- `entertainment.py` 在 `category_symbols` 为空时会回退到固定前四张神将卡，因此用户经常看到同一组卡片。

## Desired Behavior

- 当调用方显式传入 `category` 时，继续优先使用该分类。
- 当调用方未显式传入 `category` 时，根据问句内容自动归到一组受控的普通类别。
- 自动归类只覆盖当前 Beta 已允许、且语义最明确的低风险主题。
- 若问句未命中任何明确规则，保持现状，不做强行猜测。

## Category Rules

首版只补四类，目标是先让最常见问题出现可感知差异，同时降低误判风险。

- `Q-001`
  主题：合作、推进、谋望、对接、能不能成
  典型问法：合作能不能推进、这个项目能不能谈成、要不要继续对接
- `Q-002`
  主题：感情、关系、复合、相处、联系
  典型问法：能不能复合、关系要不要继续、对方还会不会联系
- `Q-004`
  主题：沟通、消息、文书、学习、考试、面试、出行安排
  典型问法：消息能不能等到、面试沟通顺不顺、考试能不能发挥稳定、这次出行顺不顺
- `Q-005`
  主题：工作、求职、职场机会、项目机会、发展选择
  典型问法：这份工作要不要去、offer 要不要接、这个机会值不值得争取

## Classification Priority

归类顺序必须固定，避免低风险关键词把高风险问题冲掉。

1. 若调用方显式传入 `category`，直接保留。
2. 若显式分类为空，先执行现有高风险关键词归类：
   `Q-009` 医疗、`Q-010` 法律、`Q-011` 投资、`Q-012` 人身安全。
3. 若不属于高风险，再执行普通问题自动归类。
4. 若仍未命中，则返回 `None` 或原始空值，保持当前兜底行为。

## Safety And Beta Constraints

- 自动归类不能改变 `build_safety` 的高风险决策。
- `Q-002` 只做关系主题归类，不允许把操控、强迫回头、越界跟踪等 blocked 问题包装成普通感情问题。
- `Q-004` 中的“出行”仅用于低风险顺利度和安排类表达；若问题明显转向安全处置，仍应交给高风险或 blocked 规则。
- `Q-005` 仅用于工作、求职、机会判断；涉及股票、基金、买卖时仍必须归入 `Q-011`。
- 不新增对 `Q-003`、`Q-006`、`Q-007`、`Q-008`、`Q-014`、`Q-015` 的自动推断，避免一次放太宽。

## Implementation Shape

- 在 `safety.py` 中新增普通问题关键词表与匹配函数。
- `normalize_category` 保持单一入口，内部按优先级先查显式分类、高风险分类，再查普通分类。
- `category_symbols` 无需改协议，只要 `normalize_category` 能返回稳定 `Q-*`，现有链路就会自动带出不同神将组合。
- `engine.py`、`interpreter.py`、`entertainment.py` 保持最小改动或不改动。

## Testing

需要先补失败测试，再写实现。

- 为 `normalize_category` 增加单元测试：
  - 无显式分类时，合作问句命中 `Q-001`
  - 感情问句命中 `Q-002`
  - 沟通/学习/出行问句命中 `Q-004`
  - 工作/求职/机会问句命中 `Q-005`
  - 高风险词优先于普通词
  - 未命中规则时保持 `None`
- 为接口增加行为测试：
  - `text-interpret` 在未传 `category` 的常见问句下返回非空 `category_symbols`
  - 不同主题问句返回不同的 `persona_lines` 组合
- 保持现有安全测试和前端测试通过。

## Non-Goals

- 不做模型分类。
- 不做语义向量检索。
- 不重写神将卡选择算法。
- 不改变 Beta 白名单和公开发布范围。
