# 第 9 阶段运维复盘报告 v0.1

## 当前结论

系统已具备小范围上线运维所需的本地闸门、指标、反馈分流和暂停恢复机制。

由于第 8 阶段发布准入仍可能因为专家审校待处理而返回 `blocked`，第 9 阶段默认不绕过闸门，不强行开放测试用户。

## 观测入口

- 运维状态：`GET /api/ops/status`
- 运维指标：`GET /api/ops/metrics`
- 反馈分流：`GET /api/ops/feedback/triage`
- 记录事件：`POST /api/ops/event`
- 手动暂停：`POST /api/ops/pause`
- 恢复检查：`POST /api/ops/resume`

## 复盘指标

- 会话数、完成率、模式使用分布。
- 反馈数量和反馈类型分布。
- 安全拦截数、高风险触发数。
- API 失败、Realtime 失败、分享报告生成数。
- P0/P1 安全事件和手动暂停次数。

## 处理策略

- `blocked`：输出阻断复核报告，不开放测试用户。
- `canary`：仅开放 20-50 名受邀用户，并持续记录反馈与事件。
- `paused`：停止正常讲盘，只显示维护/安全说明和反馈入口。

## 阻断项处理优先级

1. 高风险漏拦截、无出处判断、确定性承诺、隐私或版权投诉。
2. Realtime 绕过工具或工具调用失败。
3. 专家审校待处理规则。
4. 出处不足、排盘疑问、理解困难和语音体验问题。
